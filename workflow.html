StratForge Architecture & Build Notes

Technical breakdown of how StratForge parses GRID Series State JSON, normalizes VALORANT map coordinates across Ascent, Haven, and Split, computes deterministic setup win-rate deltas and Operator profiles, and runs automated Node + Playwright regression checks.

Runtime: Pure ESM (Node + Browser) Tests: node:test (7/7) Maps: 3 (42 callouts) E2E: Playwright 1440px + 390px

Pipeline Overview

Implementation Stages

01 / Schema-First Parsing

Single Parser Path for Presets and Live Imports

Instead of maintaining separate mock shapes for UI demos, all three bundled presets emit official GRID GraphQL data.seriesState.games[].rounds[] payloads and run through parseGridSeriesState() on load.

const raw = getRawPresetJson('c9-sen-ascent'); const match = parseGridSeriesState(raw);
02 / Coordinate Normalization

World Space to 0..1000 Radar Projection

Telemetry files can arrive in raw engine units (-5200..6800) or normalized radar space (0..1000). normalizeCoordinate() auto-detects input bounds and resolves nearest callouts across 42 zones on Ascent, Haven, and Split.

if (rawX >= 0 && rawX <= 1000) return { x: rawX, y: rawY }; return mapWorldBoundsToRadar1000(spec.worldBounds, rawX, rawY);
03 / Deterministic Math

Reproducible Clustering and Vulnerability Scoring

All scouting outputs are deterministic: Euclidean centroid clustering (r = 64), deployed-vs-baseline setup win-rate delta, >=$4,700 vs glass-cannon Operator buy detection, and a 0-100 Trade-Death Vulnerability index.

rawVuln = untradedRatio * 45 + glassCannonRate * 20 + earlyPeekDeathRatio * 20 + midRoamPct * 15;
04 / JetBrains + Automated E2E

WebStorm Run Configs and Playwright Gate

The repo ships with .idea/workspace.xml run configurations for the local ESM server and node --test. Before each deploy, scripts/verify-e2e.mjs checks zero console errors, round/pin interactions, JSON import, and 0px overflow at 1440px and 390px.

npm test # 7/7 deterministic unit checks node scripts/verify-e2e.mjs # headless Playwright audit

Engineering Takeaways

  • Zero-build shared ES modules: Running the exact same src/maps.js, src/gridParser.js, and src/analytics.js files in Node tests and the browser kept test runs under 150ms and removed bundler/sourcemap friction in WebStorm.
  • AI in the build loop, deterministic math at runtime: Coaches need auditable numbers during timeouts. Using AI tooling to write and test deterministic rules gives instant recalculation on dropped GRID JSON files with zero API latency or hallucination risk.
  • Layout verification catches real bugs: Checking scrollWidth <= innerWidth and interactive clicks in headless Chromium prevented mobile overflow and ensured the tactical map stays usable on both 1440px monitors and 390px phones.
